# Melody — Local Music Recommender + TWSMA

A local-first college project combining a browser music library, explainable content-based recommendations, a backend hybrid recommendation system, catalogue metadata, and music-news text analytics. Local audio is played by the browser and is never uploaded.

## Run on Windows

Use Python 3.11+ and Node.js LTS. From the project root:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }  # Optional; preserve existing keys
python -m venv .venv         # Skip if the project environment already exists
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
```

Keep existing `.env` values and API keys. To enable Last.fm charts, open the project-root `.env`, set `LASTFM_API_KEY=your_lastfm_api_key` using a key from your Last.fm account, save the file, and restart the backend. The key stays on the backend and is never sent to the frontend. If the key is missing or invalid, the app reports that provider charts are unavailable; it does not substitute catalogue records. MusicBrainz search works without a key and should use a descriptive User-Agent. RSS feed URLs are configured by `MUSIC_RSS_FEEDS`. YouTube configuration may remain in older `.env` files but is not used by the application.

Start the backend in a PowerShell window at the project root:

```powershell
python backend/run_backend.py
```

Start the frontend in a second PowerShell window:

```powershell
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

Open <http://127.0.0.1:5173>. The API documentation is at <http://127.0.0.1:8000/docs>.

## Local library and playback

Choose **Import music** or drop supported audio files on the app. Multiple MP3, WAV, M4A, FLAC, OGG, AAC, AIFF, and other browser-recognized audio files can be imported together. File bytes remain in browser IndexedDB; object URLs are released when files are removed or the page closes. The player uses HTML audio metadata, time, seek, volume, playback, pause, and ended events. Unsupported codecs produce an error in the app.

The importer reads ID3 title, artist, album, genre, and embedded artwork from MP3 files. Other files use `Artist - Title` filename parsing when present; metadata that cannot be read is shown as **Unknown**. Duration comes from browser decoding. Add genre-tagged files to build genre playlists. If browser storage is unavailable or full, the app reports that it could not save the import.

Open **Genre Playlists** to set up or rescan the local genre library. Embedded genre tags remain labeled as embedded metadata; your assignments are labeled as manually confirmed and survive rescan and refresh. Uncertain tracks remain in **Unknown / Needs Review**. Genre cards, search, sorting, bulk assignment, and playable queues operate on the existing IndexedDB files without reimporting them. Search results from iTunes can play a preview only when the query is entered as `Title - Artist` and the returned title and artist both match exactly; other results remain metadata-only and may link to the provider.

MusicBrainz catalogue records are metadata-only. A seed recommendation can play a matching local file or an official Apple-supplied preview when both a verified preview URL and its Apple Store link are present. Preview audio is streamed directly by the browser, is not downloaded or persisted, and is shown with Apple attribution. The app does not require or use a YouTube key.

## Smart queue demonstration

1. Start the backend and frontend as described above, then import a few audio files in **My Library**. Local file bytes and the existing library stay in this browser.
2. Play a song from any section. The bottom player is the shared now-playing seed; open **Queue** to view **Recommended** and **Playback queue** separately.
3. The recommendation list is generated by `POST /api/recommendations/seeded`. It ranks real catalogue metadata, uses only non-synthetic seed-linked interactions and verified Last.fm evidence when available, and discloses unavailable signals. A track matching an imported file plays locally; a verified Apple result may play its provider preview; metadata-only results are not playable.
4. Use **Play Next**, **Add to Queue**, or **Play Recommended Queue** to change playback order. Simply switching songs does not replace the current queue. Use **Refresh Recommendations** after the seed-change notice to generate for the newly playing song.
5. In **For You**, keep the playing track as the default seed, choose a different local track, select a genre, or use **Use as seed** beside a MusicBrainz or Apple Search result. Select **Generate Recommendations**; the ranked list uses the same backend endpoint as Queue.
6. Open **Recommendation Insights** to review the candidate funnel, effective weights, signal availability, ranking reasons, and the separate **Apple Catalogue Discoveries** list. Search previews are available only for an exact `Title - Artist` query; the Apple Store link and “Provided courtesy of iTunes” attribution are shown with each preview.
7. Restart the backend after changing feed settings, open **TWSMA Analytics**, and select **Sync RSS feeds** to retrieve new entries. While a song is playing, **Signals for the current song** shows stored RSS articles that exactly mention the selected song context; the view labels publication time, source, matched entity, relevance, and article-text sentiment. Social posts are reported unavailable unless an authorized source is configured.

The browser sends seed metadata, not local audio bytes, to the backend. Collaborative recommendations therefore remain limited unless genuine non-synthetic interaction records linked to that seed exist. The Last.fm API key remains server-side. Apple results and RSS coverage depend on network access and provider availability.

## Recommendation viva

The local recommender represents track title, artist, album, and genre terms as TF-IDF vectors. It compares vectors with cosine similarity, ranks the available local tracks, and shows the numeric similarity plus matching metadata. When multiple tracks are liked, it averages pairwise similarities to form a combined preference. Missing metadata does not receive a fabricated score.

The backend hybrid recommender remains separate. It combines available content similarity, collaborative filtering, provider chart signals, and TWSMA text sentiment using configured weights. When a signal is unavailable, it renormalizes the effective weights over the signals that are available. Its recommendation trace contains scores, evidence, candidate counts, and data sources. Initial demo interactions are synthetic; catalogue records are provider metadata.

## TWSMA viva

The backend fetches configured music-news RSS feeds, keeps each article's source URL and publication date separate from retrieval time, strips markup, tokenizes text, removes stopwords, and calculates VADER sentiment. It reports sentiment counts, common terms, catalogue artist mentions, and dated sentiment counts where publication dates exist. These are music-news results, not social-media posts.

## Known limitations

- Audio tag extraction is implemented for MP3 ID3 tags; other formats use filename metadata and browser duration.
- Content-based similarity depends on real metadata overlap. Tracks with too little metadata are skipped with an explanation.
- Browser IndexedDB quotas vary by browser and disk space.
- Catalogue search needs network access for new MusicBrainz results. Trending is shown only when configured Last.fm returns chart records; MusicBrainz results are never presented as rankings.
- RSS availability, publication dates, and article coverage depend on the configured feeds.
- Local song files are not sent to the backend, so the backend hybrid model operates on catalogue records and demo interactions.
